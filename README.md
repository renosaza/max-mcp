# max-mcp

Локальный MCP-сервер для работы с пользовательской сессией MAX через OpenAI Codex CLI, Claude Code и другие MCP-клиенты. Он помогает находить чаты и сообщения, читать и выгружать публикации каналов, скачивать вложения и отправлять сообщения или файлы.

> [!WARNING]
> Проект использует неофициальный клиент `maxapi-python` и пользовательскую сессию. Протокол MAX может измениться без предупреждения, а автоматизация может повлечь ограничения аккаунта. Для экспериментов лучше использовать отдельный аккаунт и не делать массовых рассылок.

## Возможности

| Инструмент | Назначение |
|---|---|
| `list_chats` | Список диалогов, групп и каналов |
| `find_chats` | Поиск чата по названию или имени собеседника |
| `get_chat` | Данные чата или канала |
| `get_user` | Профиль пользователя и ID личного диалога |
| `read_messages` | История сообщений с пагинацией |
| `search_messages` | Поиск подстроки по истории выбранного чата |
| `list_channel_posts` | Публикации канала, реакции и статистика |
| `dump_channel` | Выгрузка канала частями до 1000 публикаций за вызов |
| `list_attachments` | Вложения сообщения с индексами |
| `download_attachment` | Скачивание вложения в разрешённый каталог |
| `send_message` | Отправка сообщения или ответа |
| `send_file` | Отправка файла, фото или видео |

Параметры и форматы ответов описаны в [справочнике инструментов](docs/TOOLS.md).

## Требования и установка

Нужны macOS или Linux, Python 3.11–3.13, [`uv`](https://github.com/astral-sh/uv) и один MCP-клиент с поддержкой stdio.

```bash
git clone https://github.com/renosaza/max-mcp.git ~/max-mcp
cd ~/max-mcp
uv sync --frozen
```

## Авторизация

Выберите один способ входа. Для QR-кода выполните команду и отсканируйте код через привязку нового устройства в мобильном приложении MAX:

```bash
uv run --frozen max-mcp-login login-qr
```

Для входа по номеру телефона:

```bash
uv run --frozen max-mcp-login login-sms --phone +79991234567
```

Сессия хранится в `~/.max-mcp/`: каталог защищается правами `0700`, файлы сессии — `0600`. Для SMS настроен профиль Android **26.35.1** с `maxapi-python==2.4.1`; PyMax загружает его fingerprint из [каталога версий](https://hashes.pymax.org/versions.json). Если каталог недоступен, можно использовать встроенную в PyMax версию `26.28.0` через `MAX_MCP_APP_VERSION` и при SMS-входе, и при запуске сервера. QR-вход использует web-профиль PyMax. Для повторной авторизации см. [диагностику](docs/TROUBLESHOOTING.md).

## Подключение MCP-клиента

Выберите свой клиент; устанавливать оба не требуется. Если проект находится в другом каталоге, замените `"$HOME/max-mcp"` на его путь.

### Codex CLI

```bash
codex mcp add max-mcp -- "$(command -v uv)" run --frozen --directory "$HOME/max-mcp" max-mcp
codex mcp list
codex mcp get max-mcp
```

Начните новый сеанс Codex и, например, попросите показать последние чаты без отправки сообщений. Если подключение обрывается по тайм-ауту, добавьте в существующую секцию `[mcp_servers.max-mcp]` файла `~/.codex/config.toml`:

```toml
startup_timeout_sec = 45
tool_timeout_sec = 120
```

### Claude Code

```bash
claude mcp add max-mcp --scope user \
  -- uv run --frozen --directory "$HOME/max-mcp" max-mcp
claude mcp list
```

В открытой сессии Claude Code выполните `/mcp` и переподключите сервер либо начните новый чат. Другому MCP-клиенту передайте команду `uv run --frozen --directory <путь-к-max-mcp> max-mcp` через stdio.

## Примеры работы

В MCP-клиенте можно попросить: «Найди чат с Иваном, покажи последние сообщения и найди в них слово „договор“. Ничего не отправляй». Типичная последовательность вызовов:

1. `find_chats(query="Иван")` — найти подходящий чат и взять его `chat_id`.
2. `read_messages(chat_id=123456)` или `search_messages(query="договор", chat_id=123456)` — прочитать историю или найти сообщения.
3. `list_attachments(chat_id=123456, message_id="116691985249148380")` — получить индексы вложений выбранного сообщения.
4. `download_attachment(chat_id=123456, message_id="116691985249148380", attach_index=0)` — сохранить выбранное вложение.

Числа в примере условные: используйте идентификаторы из ответов MAX. Для больших ID сообщений передавайте строковое поле `message_id`, чтобы избежать округления в JavaScript; числовое поле `id` также сохраняется. Перед отправкой через `send_message` или `send_file` проверяйте получателя, текст и путь к файлу.

## Каталоги и настройки

Переменные окружения должны быть доступны процессу MCP-сервера; после изменения настроек перезапустите его. Для SMS-входа и сервера используйте одинаковое значение `MAX_MCP_APP_VERSION`.

| Переменная | Назначение и значение по умолчанию |
|---|---|
| `MAX_MCP_APP_VERSION` | Версия Android-профиля для SMS: `26.35.1` |
| `MAX_MCP_SEND_ROOTS` | Разрешённые каталоги для отправки: существующие `~/Downloads`, `~/Documents`, `/tmp` |
| `MAX_MCP_DOWNLOAD_ROOTS` | Разрешённые каталоги для скачивания: существующий `~/Downloads` |

Списки каталогов задаются через `:` и заменяют значения по умолчанию, например `MAX_MCP_DOWNLOAD_ROOTS="$HOME/Downloads:$HOME/Documents"`. Каталог назначения должен существовать; если он не указан при скачивании, используется первый разрешённый каталог. Файл для отправки должен существовать. Защищённые каталоги, в том числе `~/.ssh`, `~/.aws`, `~/.max-mcp`, `/etc` и `/var`, остаются запрещены. Конечный файл для отправки и каталог назначения не должны быть символьными ссылками.

Максимальный размер отправляемого или скачиваемого файла — 2 ГиБ. Скачивание поддерживает FILE, PHOTO, VIDEO и AUDIO и допускает только HTTPS на `max.ru`, `oneme.ru`, `okcdn.ru`, `mycdn.me` и их поддоменах; перенаправления проверяются. Существующие файлы не перезаписываются.

## Обновление

В существующем клоне проверьте и сохраните свои локальные изменения, затем выполните:

```bash
cd ~/max-mcp
git switch main
git pull --ff-only
uv sync --frozen
```

Перезапустите MCP-сервер или переподключите его в клиенте. Повторно входить и удалять сессию для обычного обновления не требуется.

## Ограничения

- Вход, скачивание и отправка с реального аккаунта MAX не тестировались; совместимость проверялась по каталогу fingerprint и публичным API PyMax.
- Поиск сообщений последовательно читает историю выбранного чата. `find_chats` ограничивает обход: `directory_truncated` предупреждает о возможной неполноте, а `unresolved_users` — о собеседниках, чьи имена не удалось получить.
- Полная выгрузка большого канала требует нескольких вызовов `dump_channel`. Схема `stats` и `reaction_info` зависит от ответа MAX; отправитель может возвращаться только числовым идентификатором.
- При изменении внутреннего протокола MAX может потребоваться обновление `maxapi-python` или кода сервера.
