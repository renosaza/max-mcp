# max-mcp

Локальный MCP-сервер для работы с пользовательской сессией MAX из Claude Code и других MCP-клиентов.

## Возможности

| Инструмент | Назначение |
|---|---|
| `list_chats` | Список диалогов, групп и каналов |
| `get_chat` | Данные одного чата или канала |
| `read_messages` | История сообщений с пагинацией |
| `search_messages` | Поиск подстроки по истории выбранного чата |
| `list_channel_posts` | Публикации канала, реакции и статистика |
| `dump_channel` | Пакетная выгрузка канала до 1000 публикаций за вызов |
| `send_message` | Отправка сообщения или ответа |
| `send_file` | Отправка файла, фото или видео |

> [!WARNING]
> Проект использует неофициальный клиент `maxapi-python` и пользовательскую сессию. Протокол MAX может измениться без предупреждения, а автоматизация может повлечь ограничения аккаунта. Для экспериментов лучше использовать отдельный аккаунт и не делать массовых рассылок.

## Требования

- macOS или Linux;
- Python 3.11–3.13;
- [`uv`](https://github.com/astral-sh/uv);
- Claude Code или другой клиент с поддержкой MCP stdio.

## Быстрый запуск

### 1. Установка

```bash
git clone https://github.com/renosaza/max-mcp.git ~/max-mcp
cd ~/max-mcp
uv sync --frozen
```

### 2. Авторизация

По QR-коду:

```bash
uv run max-mcp-login login-qr
```

В мобильном приложении MAX откройте привязку нового устройства и отсканируйте QR-код из терминала.

По номеру телефона:

```bash
uv run max-mcp-login login-sms --phone +79991234567
```

Сессия хранится в `~/.max-mcp/`. Каталог получает права `0700`, файлы сессии — `0600`.

### Контейнеры и S3/FUSE state

По умолчанию сервер строго проверяет, что `~/.max-mcp` и `session.db` не являются
символьными ссылками, имеют ожидаемый тип и принадлежат текущему пользователю. На
обычных локальных дисках это поведение менять не нужно.

Для cloud-only окружений, где state подключён через S3/FUSE и файловая система
возвращает синтетический UID или не поддерживает `chmod`, можно явно включить:

```bash
export MAX_MCP_ALLOW_SYNTHETIC_UID=1
export MAX_MCP_BEST_EFFORT_CHMOD=1
```

Эти флаги предназначены только для доверенного приватного cloud-volume. Они не
отключают проверки на символьные ссылки, тип файла/каталога и ошибки чтения, а
`MAX_MCP_BEST_EFFORT_CHMOD` игнорирует только `EPERM`, `EOPNOTSUPP` и `ENOTSUP`
от операции `chmod`.

### 3. Подключение к Claude Code

```bash
claude mcp add max-mcp --scope user \
  -- uv run --directory "$HOME/max-mcp" max-mcp
```

Проверка:

```bash
claude mcp list
```

В уже открытой сессии Claude Code выполните `/mcp` и переподключите сервер либо начните новый чат.

## Примеры запросов

```text
Покажи последние 20 чатов MAX.
```

```text
Найди в чате 123456 сообщения со словом «договор», просмотрев не больше 1000 сообщений.
```

```text
Выгрузи публикации канала -69531237780213 частями и сохрани результат в JSON.
```

```text
Отправь в чат 123456 файл /Users/me/Documents/report.pdf с подписью «Отчёт».
```

Перед операциями записи проверяйте `chat_id`, текст и путь к файлу.

## Отправка файлов

По умолчанию разрешены файлы только из:

- `~/Downloads`;
- `~/Documents`;
- `/tmp`.

Собственный список каталогов задаётся через `MAX_MCP_SEND_ROOTS`:

```bash
export MAX_MCP_SEND_ROOTS="$HOME/Desktop:/data/exports"
```

Пути внутри `~/.ssh`, `~/.aws`, `~/.max-mcp`, `/etc`, `/var` и системного хранилища ключей macOS запрещены даже при расширенном списке. Конечный путь не должен быть символьной ссылкой.

## Повторная авторизация

```bash
rm -f ~/.max-mcp/session.db \
      ~/.max-mcp/session.kind \
      ~/.max-mcp/session.phone

cd ~/max-mcp
uv run max-mcp-login login-qr
```

## Ограничения

- поиск сообщений выполняется локально последовательным чтением истории;
- схема `stats` и `reaction_info` зависит от ответа MAX и не зафиксирована;
- отправитель сообщения может возвращаться только числовым идентификатором;
- полная выгрузка большого канала требует нескольких вызовов `dump_channel`;
- после изменения внутреннего протокола MAX может потребоваться обновление `maxapi-python` или кода сервера.
